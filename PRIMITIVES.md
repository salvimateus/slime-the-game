# Primitives

Lives at the project root. Status is `confirmed` when the implementation was read and `inferred` otherwise; `pending` marks a piece whose code is not committed on the integration branch.

## core

- **`Tuning`** (autoload), `autoload/tuning.gd`, confirmed, pending
  One place for gameplay, feel and GPU-cost numbers. Many fields derive from other fields once at load (most scale with `character_scale`), so a runtime change to a base field does not reach them; a value that a script reads in `_ready` (shader parameters, pool caps, body point count) also changes only after a scene reload. `_init()` merges `temperature_haptic_presets` into `haptics_presets`. Two scripts write it at runtime through `Tuning.set()`: [[PRIMITIVES#Quality]] sets the fields that its levels own, and the perf panel (`autoload/perf_panel.gd`) sets the bool fields in its `SWITCHES`. A panel flip of a field that Quality owns is an override until the next level change, saved in the `overrides` section of `user://perf.cfg`; the other switches are saved in its `systems` section and loaded at boot. A Harness run without `--user-settings` does not read or write `perf.cfg` (see [[PRIMITIVES#Harness]]). Every field named `decor_*` or `ground_*` is part of the decoration cache key of [[PRIMITIVES#LevelBuilder]]. Contract: `var` fields only, plus the `LAYER_*` physics layer bit constants; `LAYER_PROPS`, `LAYER_ENEMIES`, `LAYER_ZONES` and `LAYER_GRATES` have no name in `project.godot` `[layer_names]`. `LAYER_GRATES` stops the solid player and props, while the melted player, goo pieces and droplets pass it.
  Consumers: 60 (every script except `fire_quad.gd`, `shape_batch.gd`, `decor_layer.gd`, `decor_painter.gd`, `mesh_section.gd`, `safe_area.gd`, `input_hints.gd`, `strings.gd` and `level_01.gd`).
- **`Game`** (autoload), `autoload/game.gd`, confirmed, pending
  Session state, seeded RNG, input actions, analog trigger reads and the signals that announce gameplay changes. Every goo mass that appears or vanishes goes through `report_lost()` or `report_gained()`, so `goo_balance()` stays 0.0. `main.gd` calls `reset_session()` on every scene load, which keeps only `seed_value`. Actions are added in code by `_register_input()`, and an action that already exists in the InputMap keeps its own events; `aim` and `fire` are analog triggers, read through `trigger_held()` and `trigger_just_pressed()` with the `Tuning.trigger_press` and `trigger_release` thresholds. Quit through `quit_game()`, which stops every sound before `get_tree().quit()` so no stream leaks at shutdown; Escape and the Android back button call it. Contract: signals `player_damaged`, `goo_absorbed`, `goo_color_absorbed`, `goo_lost`, `goo_gained`, `mass_changed`, `player_died`, `respawn_requested`, `player_respawned`, `checkpoint_reached`, `goal_reached`, `level_started`, `prop_absorbed`, `prop_dropped`, `prop_shot`, `prop_bounced`, `prop_shattered`, `target_hit`, `enemy_died`, `barrier_broken`, `player_moved`, `temperature_event`, each emitted by its `report_*()`, `request_respawn()`, `set_checkpoint()` or `start_level()` method, except the direct `goo_lost` emits of [[PRIMITIVES#GooPiece]]; `report_lost(amount, reason, emit_event = true)`; `rng`, `seed_value`, `tick` (stops at the goal), `input_tick` (keeps counting from level load, read by scripted input), `sim_time`, `level_running`, `respawn_point`, `checkpoint_id`, `kill_y`, `deaths`, `goo_lost_total`, `goo_gained_total`, `goo_recovered_total`, `player`, `field`, `props`, `TRIGGER_ACTIONS`; `reseed()`, `reset_session()`, `start_level()`, `set_checkpoint()`, `request_respawn()`, `trigger_held(action)`, `trigger_just_pressed(action)`, `summary()`, `goo_balance()`, `quit_game()`.
  Consumers: 25 files (Player, Face, GooField, GooPiece, GooDroplets, Hazard, Throwable, prop layer, ember pool, Fire body fire and fire patch, LevelBuilder decoration layout and live layer, Juice, TouchControls, Harness, Mite, Barrier, Checkpoint, Goal, Hint, Background, HUD, ScreenFX, `main.gd`).
- **`Harness`** (autoload), `autoload/harness.gd`, confirmed, pending
  Lets a CLI run with no human capture frames, freeze time, feed scripted input, fake devices and log state; with no argument after `--` it does nothing. Arguments are the keys of `ARG_KINDS`. Action commands are `<tick> <action>[+|-|:N]` and `<tick> stick=<degrees>,<force>|off`, with the Harness action names in `INPUT_ACTIONS`, not the InputMap names; device commands (`touch=`, `drag=`, `lift=`, `key=`, `pad=`, `axis=<axis>,<value>`, `joy=on|off`) inject real input events, `pad=`, `axis=` and `joy=` do not switch to touch mode (`PAD_PREFIXES`), and a run that mixes action and device commands drops the device commands. Log events are connected in `_connect_events()` and `_connect_touch_events()`, and other scripts add one through `log_event()` (the Player writes its goo pull events this way). A logged run writes a `PROPS` line from `Game.props.audit()` before `SUMMARY`, and `--perf-summary` adds a `PERF_SUMMARY` line through the perf panel `begin_run()` and `run_summary()`. `--juice-log` turns on `juice_log`: Juice (`hitstop()`, `slowmo()`, `shake()`, `punch()`) and Sfx (`play()`) then write `EVENT juice` and `EVENT sfx` lines through `log_juice()`, with the calling `file:line`, only in a logged run. The quality arguments (`--quality=`, `--render-scale=`, `--quality-log`, `--quality-governor`, `--quality-save=`, `--slow-frame=`, `--quality-phone`, `--quality-fake-busy=`) are in `ARG_KINDS` only so that the Harness accepts them; [[PRIMITIVES#Quality]] reads them, and any of them turns the Harness on. A scripted run (any argument in `SCRIPTED_RUN_ARGS`) sets `blocks_real_input` in `_init()`, before any `_ready()`: Harness then drops every input event that it does not inject, and moves every InputMap event to the device `Tuning.harness_device`, which its injected key, pad button and pad axis events carry, so a real device never reaches the game. Code that reads a real device directly asks Harness first: `ignores_input()` for an input event or a pad signal, `connected_pads()` in place of `Input.get_connected_joypads()`, and `blocks_real_input` for a mouse button. A Harness run reads and writes neither `user://perf.cfg` nor `user://quality.cfg` unless `--user-settings` is given (`uses_user_settings()`); `--quality-save=<file>` still writes its own file. In a debug build it runs the cargo deformation check at boot (see [[PRIMITIVES#SlimeBody]]). It sets the Juice haptics `forced_mode` and `logging` for runs with no device. `safe_insets` fakes a notch through `scripts/ui/safe_area.gd`, the static helper that HUD, TouchControls and the perf panel use for the safe screen rect (the display safe area on mobile, minus these insets). Contract: `spawn_position(level)` (a marker name or an `x,y` tile; an unknown name logs an error and returns the level start), `has_scripted_input()`, `intent_at(tick)` (the Player `intent` keys except `aim_from_mouse`), `log_event(event_name, data)`, `log_juice(event_name, data)`, `juice_log`, `blocks_real_input`, `uses_user_settings()`, `connected_pads() -> Array[int]`, `ignores_input()`, `spawn_override`, `mass_override`, `hide_hud`, `hide_hints`, `force_touch`, `injecting`, `safe_insets`, `open_perf_panel`, `pad_name`, `temperature_override`, `burn_override`.
  Consumers: 11 (Player, Juice with its haptics child, Sfx, TouchControls, InputGlyphs, LevelBuilder, Hint, HUD, perf panel, `safe_area.gd`, `main.gd`).
- **`Quality`** (autoload), `autoload/quality.gd`, confirmed, pending
  Quality levels (`LOW`, `MEDIUM`, `HIGH`), an automatic mode that follows the real frame time, and the render resolution; a level only changes what the player sees, never the gameplay. A level owns the `Tuning` fields in `LEVEL_FIELDS` (`fx_fire_rich`, `goo_gloss`, `fx_decor_motion`, `fx_bg_detail`) and sets them through `Tuning.set()` at each level change, so code that wants another value for those fields goes through a level, and a perf panel flip is only an override until the next level change. The automatic mode steps one level down when the game cannot hold `Tuning.quality_target_fps`, steps up only after a long calm wait, and never retries on this GPU a step that failed its probe. With no GPU time reading, a step up also passes when the calm frames hold the budget, their miss share stays within `Tuning.quality_up_miss_share`, and script and draw time stays under `quality_up_script_share` of the budget. The ladder has four steps on every device. On a phone (or with `--quality-phone`) a new install starts at Medium, and High reached by a climb must also keep the mean frame time within `Tuning.quality_hold_factor` of the Medium reference taken just before the climb (saved as `hold_ref_ms`); when it does not, the mode measures the same scene at Medium for `quality_check_window`, blocks High for the session only (never saved) when Medium is clearly faster, and else returns to High with the reference raised. It runs only in a window at a free frame rate, unless `--quality-governor` forces it. The lowest step renders at the base resolution (`content_scale_mode` viewport) only when the window has clearly more pixels than the base layout. The mode, the render mode and the learned step are saved in `user://quality.cfg` per GPU adapter, and a run with any user argument neither reads nor writes it, unless it passes `--user-settings` or names its own file with `--quality-save=`; Quality parses these arguments itself, because it loads before Harness. `warm_up()` renders the highest level for a few frames behind the loading cover, so a later step up compiles nothing. It reads `PerfPanel.last_script_and_draw_ms()` for the busy time and calls `PerfPanel.clear_overrides()` and `apply_overrides()`. Contract: signal `changed`; enums `Level`, `Mode`, `RenderMode`; `LEVEL_FIELDS`, `MODE_NAMES`, `RENDER_NAMES`; `level()`, `base_resolution()`, `mode()`, `render_mode()`, `set_mode(value)`, `set_render_mode(value)`, `cycle_mode()`, `cycle_render_mode()`, `owns(field)`, `level_value(field)` (null for a field it does not own), `describe()` (with the drawn render size: the window size, or the viewport texture size at base resolution), `warm_up()`, `wants_render_time()`; command line `--quality=auto|high|medium|low`, `--render-scale=auto|full|base`, `--quality-log`, `--quality-governor`, `--user-settings`, `--quality-save=<file>`, `--slow-frame=<ms per step>[@from-to]`, `--quality-phone` (the phone rules on any device), `--quality-fake-busy=<ms>` (adds busy time and hides the GPU time).
  Consumers: 1 (perf panel, which also calls `warm_up()` for `main.gd`); readers of its fields: Fire (`fx_fire_rich`), GooField (`goo_gloss`), the LevelBuilder decoration live layer (`fx_decor_motion`), Background (`fx_bg_detail`).

## input

- **`TouchControls`** (autoload), `autoload/touch_controls.gd` with `scripts/ui/touch/touch_stick.gd` and `touch_button.gd`, confirmed, pending
  On-screen move stick and buttons, and the source of the current input mode (`touch`, `pad` or `keys`). Touch reaches gameplay only through `Input.action_press()` and `action_release()` on the same InputMap actions as the pad, so gameplay reads no touch state. A press stays down at least `Tuning.touch_min_hold` and `touch_min_hold_ticks`, and the release of the aim drag is the shot (`fire` presses again until `Game.prop_shot`). The first mode is touch only with `Harness.force_touch`, or with a touchscreen, no pad and the `mobile`, `web_android` or `web_ios` feature, so a desktop with a touchscreen starts in keys. After that the last input wins: the inputs of one frame settle at its end, a mode then holds for `Tuning.input_mode_hold`, a pad axis switches only past `PAD_AXIS_SWITCH`, and system keys and emulated mouse events do not switch. A pad that connects before the first input takes the pad mode; when the last pad disconnects in pad mode, the mode falls back to touch (touch-first or forced) or keys. With `force_touch`, only input sent while `Harness.injecting` is true changes the mode. It shows only in touch mode while a player is in the tree, and a control that hides releases its action. Each drawn element has its own RenderingServer canvas item and [[PRIMITIVES#ShapeBatch]], and redraws only when its `visual_key()` changes, gated by `Tuning.fx_touch_redraw`; the idle stick fades while the slime is under it. [[PRIMITIVES#InputGlyphs]] draws small copies of the stick and the button. Contract: signals `input_mode_changed(mode)` and `action_changed(action, pressed)`; `touch_enabled`, `input_mode`, `MODE_TOUCH`, `MODE_KEYS`, `MODE_PAD`; `is_touch_mode()`, `is_showing()`, `warm_up()`; stick and button `visual_key()`, `update(delta)`, `draw(batch)`.
  Consumers: 7 (Juice haptics, InputGlyphs, Hint, HUD, perf panel, Harness, `main.gd`).
- **`InputGlyphs`**, `scripts/ui/input_glyphs.gd` with its data table `scripts/ui/input_hints.gd`, confirmed, pending
  Draws the input icons of one hint in code, in the current style: keycaps and mouse, Xbox or PlayStation pad, or small touch controls. Icons come from `InputMap.action_get_events()`, so a binding change changes them; the style comes from [[PRIMITIVES#TouchControls]] `input_mode` and the pad name (`Harness.pad_name` first). It does not redraw by itself: a caller calls `update(delta)`, compares `visual_key()` and calls `queue_redraw()` only on a change, and calls `refresh()` when the input mode changes or a pad connects. With no icon for the style, every row shows only its label through `Strings.text()`. `input_hints.gd` holds only `HINTS` (`{hint_key: [rows]}`; a row is `{"steps", "label"}` plus optional `"touch"`; an action step is `{"actions", "press"}` with `press` one of `tap`, `hold`, `dir`, `drag`, plus optional `"join"` (`plus` or `then`), `"single"` and `"crossed"`; a state step is `{"state"}` with `flame`, `snow`, `cube` or `drop`, plus optional `"join"`); callers read it and pass the rows to `new()`. Contract: `_init(definition, unit, label_size)`, static `current_style()`, `font()`, `pad_name()`, `is_playstation_name(text)`; `refresh(for_style = &"") -> bool`, `has_icons()`, `describe()`, `update(delta)`, `visual_key()`, `draw(item, center, alpha = 1.0)`; `style`, `size`, `STYLES`, `STYLE_TOUCH`.
  Consumers: 2 (Hint, HUD).

## feedback

- **`Sfx`** (autoload), `autoload/sfx.gd`, confirmed, pending
  Bakes procedural sound presets on a worker thread from `_ready` and plays them from a voice pool, so the project has no imported audio files; the preset names are the keys of `recipes` in `_bake_all()`. `play()` and `stream()` wait for the bake to end, so `main.gd` calls `finish_bake()` behind the loading cover. A preset replays at most once per `Tuning.sfx_min_frames`, and a call inside that window or with an unknown name plays nothing (an unknown name warns once). Contract: `is_baked()`, `finish_bake()`, `play(preset, at = null, pitch = 1.0, volume_db = 0.0, jitter = -1.0)` (a finite `Vector2` or a `Vector2i` `at` plays positional, anything else plays flat), `stream(preset) -> AudioStream` (null for an unknown preset, and at once when no output can be heard, so the caller skips its own player too), `stop_all()` (stops every audio player in the tree), `set_muffle(amount)`, `bake_ms`.
  Consumers: 17 files (Game, Juice, Harness, TouchControls, Player, GooPiece, Throwable, ember pool, Fire body fire and fire patch, Saw, Mite, Barrier, Checkpoint, Goal, HUD, `main.gd`).
- **`Juice`** (autoload), `autoload/juice.gd` with its child `autoload/haptics.gd`, confirmed, pending
  Single entry point for screen-wide feedback and vibration, and the only writer of `Engine.time_scale`, so effects from many sources stack instead of the last tween winning. A new time scale applies at the end of the frame, and code that must ignore hitstop converts its delta with `real_delta()`; `aim_slowmo()` holds a gentle slow motion that stacks with `slowmo()` (the lower scale wins) and with hitstop. `shake()` and `punch()` take a source name: calls of one source less than `Tuning.juice_merge_gap` apart merge into one burst, where a call adds only its excess over the strongest call so far, and each call is capped at `Tuning.juice_shake_max` or `juice_punch_max`, so a new event kind takes its own source name. Call `reset()` before a scene reload, because time scale and muffle outlive the scene. Vibration goes only through `haptic()`, never the Input vibration API: the haptics child plays the presets of `Tuning.haptics_presets` one at a time, with cooldown, priority and rate limits, only in pad or touch mode. Juice starts the presets of gameplay events from `Game` signals; an owner starts its own presets (the Player starts `drain` and `run_start`) through `haptic()`. Contract: `camera`, `screen_fx`, `sparks` (each node registers itself and clears the reference on exit; callers check `is_instance_valid()`), `haptics` (`forced_mode`, `logging`, signal `logged`, `MODE_PAD`, `MODE_TOUCH`, `MODE_KEYS`, `play(preset, strength)`, `stop(reason = &"end")`, `current_mode()`), `haptic(preset, strength = 1.0)`, `real_delta(scaled_delta)`, `hitstop()`, `slowmo()`, `aim_slowmo(active)`, `shake(trauma, source)`, `punch(amount, source)`, `flash()`, `muffle()`, `impact(strength)`, `death()`, `celebrate()`, `reset()`.
  Consumers: 16 (Player, Throwable, ember pool, Saw, Mite, Barrier, Checkpoint, Goal, HUD, ScreenFX, GameCamera, Sparks, TouchControls, perf panel, Harness, `main.gd`).
- **`GameCamera`**, `scripts/camera/game_camera.gd`, confirmed, pending

## drawing

- **`ShapeBatch`**, `scripts/fx/shape_batch.gd`, confirmed, pending
  Batches flat shapes with a feathered edge into one `canvas_item_add_triangle_array`, so many shapes cost one draw call. A `polygon()` outline must be star-shaped around its centroid. - **`GooField`** (scene), `scenes/goo/goo_field.tscn` with `goo_field.gd`, `goo_field.gdshader` and the stain layer `scripts/goo/goo_stains.gd`, confirmed, pending
